# متابعة المبيعات والتحصيل

تطبيق ويب لمتابعة مبيعات وتحصيل المناديب وإدارة المخازن، مبني بـ React + Vite، ويستخدم Supabase كقاعدة بيانات سحابية بحيث تتزامن البيانات بين كل الأجهزة (كمبيوتر وجوال).

## 1. إعداد قاعدة البيانات (مرة واحدة فقط)

1. اذهب إلى [supabase.com](https://supabase.com) وسجّل حسابًا مجانيًا (يمكن الدخول مباشرة بحساب Google أو GitHub).
2. اضغط **New Project**، اختر اسمًا للمشروع وكلمة مرور لقاعدة البيانات (احفظها جانبًا)، واختر أقرب منطقة خادم لكم. انتظر دقيقة أو دقيقتين حتى يجهز المشروع.
3. من القائمة الجانبية اختر **SQL Editor**، افتح استعلامًا جديدًا (New query)، الصق فيه محتوى ملف `supabase/setup.sql` الموجود في هذا المجلد، ثم اضغط **Run**. هذا ينشئ الجدول الذي سيخزّن فيه التطبيق كل بياناته.
4. من القائمة الجانبية اذهب إلى **Project Settings → API**. ستجد هناك:
   - **Project URL**
   - **anon public key**

انسخ القيمتين، ستحتاجهما في الخطوة التالية.

## 2. ربط الكود بالمشروع

افتح الملف `src/App.jsx` وعدّل هذين السطرين بالقيم الحقيقية التي نسختها:

```js
const SUPABASE_URL = "https://YOUR-PROJECT-REF.supabase.co";
const SUPABASE_ANON_KEY = "YOUR-ANON-PUBLIC-KEY";
```

## 3. التشغيل محليًا (اختياري، للتجربة على جهازك)

```bash
npm install
npm run dev
```

سيفتح التطبيق على `http://localhost:5173`.

## 4. النشر على Vercel (لكي يعمل من أي جهاز)

1. ارفع هذا المجلد كمستودع (repository) على GitHub.
2. أنشئ حسابًا مجانيًا على [vercel.com](https://vercel.com) وسجّل الدخول بحساب GitHub.
3. اضغط **Add New Project**، واختر هذا المستودع.
4. Vercel يكتشف تلقائيًا أنه مشروع Vite، فقط اضغط **Deploy**.
5. بعد دقيقة ستحصل على رابط دائم مثل `https://sales-tracker-app.vercel.app` — هذا هو الرابط الذي يستخدمه الجميع من أي جهاز (كمبيوتر أو جوال) للدخول لنفس البيانات.

## ملاحظات

- كلمة مرور الإدارة الافتراضية عند أول تشغيل: `admin123` — غيّرها فورًا من "الإعدادات وواتساب" داخل لوحة الإدارة.
- كل بيانات التطبيق (المناديب، التقارير، العملاء، الأهداف، الأصناف، المخازن، التوريدات...) تُخزَّن في جدول واحد اسمه `kv_store` داخل مشروع Supabase، ويمكن معاينتها مباشرة من تبويب **Table Editor** هناك.
- قواعد الأمان المفتوحة (المستخدمة في `setup.sql`) مناسبة لأداة داخلية بحجم فريق مبيعات صغير — لأن التطبيق نفسه لديه نظام تسجيل دخول خاص به (إدارة/مناديب) يحمي الوصول.
